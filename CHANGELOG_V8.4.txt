TIMESTAMP GENERATOR V8.4
========================

Perubahan utama - Batch NPSN:

1. Logic koordinat resmi TETAP menjadi prioritas utama.
   - Jika Referensi Data Kemendikdasmen memiliki latitude/longitude valid, aplikasi memakai titik resmi seperti versi sebelumnya.
   - Fallback tidak pernah mengganti titik resmi yang sudah tersedia.

2. Fallback geocoding baru bersifat OPSIONAL.
   - Toggle: "Gunakan fallback geocoding HANYA jika koordinat resmi NPSN kosong / 0,0".
   - Default OFF.
   - Jika OFF dan titik resmi 0,0, generate tetap diblokir seperti logic lama.

3. Fallback dibuat konservatif / strict.
   - Mengambil Nama + Alamat + Desa + Kecamatan + Kabupaten/Kota + Provinsi dari halaman resmi NPSN.
   - Mencoba beberapa query geocoding, bukan satu query saja.
   - Kandidat wajib lolos reverse-geocoding administratif.
   - Kabupaten/Kota dan Provinsi wajib cocok.
   - Jika Desa/Kecamatan tersedia, minimal salah satunya wajib terkonfirmasi dan tidak boleh ada mismatch eksplisit.
   - Nama titik kandidat harus cukup mirip dengan nama satuan pendidikan.
   - Minimal dua varian pencarian harus mengarah ke area yang sama (<=150 meter), atau ada konfirmasi Google Maps bila GOOGLE_MAPS_API_KEY tersedia.
   - Jika confidence tidak cukup, generate diblokir. Program tidak memakai centroid wilayah sebagai tebakan.

4. Dukungan cross-provider opsional.
   - Tambahkan GOOGLE_MAPS_API_KEY di Streamlit Secrets untuk cross-check Google Maps.
   - Jika titik OSM dan Google saling berdekatan dan validasi wilayah cocok, status confidence menjadi VERY HIGH.
   - Tanpa Google key, fallback tetap dapat lolos dengan multi-query consensus OpenStreetMap/Nominatim jika syarat strict terpenuhi.

5. Untuk NPSN 69914723, data resmi memang memiliki koordinat 0,0, sehingga fitur fallback dapat digunakan jika toggle diaktifkan.

Catatan penting:
- Fallback geocoding bukan titik resmi Kemendikdasmen. Aplikasi sengaja lebih memilih gagal daripada mengembalikan titik yang meragukan.
- Karena sumber resmi tidak menyediakan koordinat, tidak ada metode yang bisa menjamin fallback memiliki presisi identik dengan titik resmi yang memang sudah diverifikasi. V8.4 memaksimalkan akurasi dengan validasi berlapis dan memblokir hasil ber-confidence rendah.
